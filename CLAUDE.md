# CLAUDE.md

## What this is

`mcp-server-misterfpga`: an MCP server for one or more MiSTer FPGA devices, through Zaparoo
Core's JSON-RPC WebSocket API (games, history, screenshots, NFC, updates) and SSH/SFTP
(MiSTer.ini, save backups, running core, attract mode). Sibling of `mcp-server-harmony`,
`-sofabaton`, `-webos`, `-onkyo`, `-shieldtv` and `-batocera`. docs/DESIGN.md is the approved
design, the research behind it and the decisions; read it before changing behavior.

**This is a learning project.** The owner wants to understand how MCP servers are built, so
explain the reasoning behind non-obvious changes instead of only making them. He's a
software/systems engineer: be technical and concrete, with specific examples.

## Layout

- `src/misterfpga_mcp/config.py`: settings (`config.json` `hosts` with name, model, ssh;
  `backup_dir`; `MISTERFPGA_*`), problems as sentences; `save_host` for `check`
- `src/misterfpga_mcp/zaparoo.py`: `ZaparooClient`, one WebSocket per MiSTer: ids, notifications,
  reconnect with backoff, ping/pong; `ALLOWED_METHODS` is the allow-list
- `src/misterfpga_mcp/ssh.py`: `MisterShell`: the `Command` enum (all that ever runs remotely),
  `check_path` (the SFTP path policy), pinned host keys
- `src/misterfpga_mcp/ini.py` + `ini_keys.py` (generated by `dev/gen_ini_keys.py` from
  Main_MiSTer `cfg.cpp`): parse and edit MiSTer.ini like MiSTer; key/value/section validation
- `src/misterfpga_mcp/backup.py`: hard-linked save snapshots
- `src/misterfpga_mcp/host.py`: `MisterHost`, what each tool does to one MiSTer; result TypedDicts
- `src/misterfpga_mcp/hosts.py`: `HostRegistry`, which MiSTer a call means (never guess), refs
- `src/misterfpga_mcp/server.py`: MCP tools, resource, prompt (`MCPServer` from `mcp` 2.x)
- `src/misterfpga_mcp/limits.py`: this server's rate-limit numbers (mechanism in shared
  `ratelimit.py`)
- `src/misterfpga_mcp/assumptions.py`: every unverified protocol claim (id, source, confidence,
  status)
- `src/misterfpga_mcp/track.py`: the play tracker (`track`, DESIGN §10): `HostTracker` (pure
  session logic, clock injected), `discovery_messages` (Batocera playtracker's entities), `Outbox`
  (latest retained states + waiting `session_end`s), `deliver` (aiomqtt, last will, reconnect),
  `Tracker` (one Zaparoo connection and event queue per MiSTer). Catch-up reads `media.history`
  back to the mark in `track-state.json`
- `src/misterfpga_mcp/doctor.py`, `cli.py`: `serve` (default), `check`, `call`, `doctor`,
  `track`, `simulate`
- `src/misterfpga_mcp/sim/`: `FakeDevice` (shared state), `FakeZaparoo` (aiohttp, real JSON-RPC),
  `FakeMister` (asyncssh, real SSH/SFTP chrooted to a folder), `harness.Simulation`, fixtures
  (`office` = MiSTer Pi, `family_room` = SuperStation One; *Super Metroid* on both on purpose).
  `FakeZaparoo.play` / `quit_game` act like the MiSTer's own menu; quitting writes a history
  entry. Used by tests *and* `simulate`
- Shared with the siblings via mcp-server-shared (pinned by `shared.lock`):
  `remote.py`, `logsafe.py`, `tasks.py`, `ratelimit.py`, `tests/test_{remote,logsafe,tasks,ratelimit}.py`,
  `scripts/sync_shared.py`. **Never edit them here**; change mcp-server-shared, then
  `python scripts/sync_shared.py --update`. CI's `shared-drift` job enforces it.
- `deploy/alpine/`: OpenRC services (user `mcp-mister`): `mcp-server-misterfpga` (MCP over HTTP,
  port 8716) and `mcp-server-misterfpga-track` (`run.sh track`); HTTP, Access and MQTT settings in
  `/etc/mcp-server-misterfpga/env`. Install and smoke test (which drives the service over HTTP)
- `tests/`: `conftest.py` (`sim`, `configured`, `mcp_client`), `test_tools` (contract and
  behavior through an in-process MCP `Client`), `test_safety`, `test_ini`, `test_backup`,
  `test_nfc`, `test_zaparoo`, `test_config`, `test_cli` and `test_stdio` (subprocesses),
  `test_http_tools` (these tools over HTTP with signed Access assertions; `test_remote` is the
  shared transport test), `test_track` (session logic, then the real tracker against the
  simulator and an asyncio `FakeBroker`),
  `test_recorded` (replays `doctor --dump` captures), `test_assumptions`. Async tests use anyio's
  plugin.

## Rules for changes

- **The model never supplies a path, ZapScript or a shell command.** Games launch by ref
  (`<host>/<mediaId>`), turned back into Zaparoo's own `zapScript` with `media.meta`; systems by a
  validated id. Widening `ALLOWED_METHODS` or `Command`, or `check_path`, is a design change:
  update docs/DESIGN.md §8, README and `test_safety.py` together.
- **Never guess a MiSTer** (Harmony's rule): an action without a ref or `host` acts only when
  exactly one MiSTer fits; otherwise the error names them. Refs decide; a contradicting `host` is
  an error.
- **Never replace a running game.** `launch` refuses; `return_to_menu` (destructive) is the
  explicit step.
- **Tell the model what works.** New features show up in `MisterHost.capabilities()` (a
  capability when available, a limitation that says how to fix it when not), Sofabaton's model.
- **Don't invent protocol details.** Anything not confirmed on hardware is an `Assumption`, cited
  as `# ASSUMPTION <id>` where code depends on it, in README's table and HARDWARE_VALIDATION.md.
  `test_assumptions` enforces it.
- No Zaparoo API key or pairing: legacy access is enough on MiSTer, and a key would lock out the
  Zaparoo app (DESIGN §1.4).
- **Remote access is Batocera's: Cloudflare Tunnel + Access, checked here** (DESIGN §11, Q3,
  revised 2026-10-24). `serve --http` (the Alpine service, on 127.0.0.1:8716/misterfpga/mcp) runs
  on shared `remote.py`, which verifies the Access assertion on every request and, without Access,
  serves only its own machine. The server is the only gate in front of a reboot-capable update and
  a root SSH key: Access settings go in the env file, `MCP_ALLOWED_EMAILS` is recommended, and the
  service never runs with `--insecure-no-auth`. `test_http_tools.py` covers the real tools over
  HTTP; keep it passing. Never tunnel Zaparoo (7497) or SSH directly.
- **The tracker publishes Batocera's shapes.** Topics, payload keys and HA entities match
  mcp-server-batocera's playtracker (plus `host`, `device`), so one automation covers all three
  devices; change them together or not at all. It only *reads* Zaparoo (`media.active`,
  `media.history`, notifications): no new methods on the allow-list. A late `session_start` is
  dropped, `session_end` waits (Batocera's outbox rule). Session times are the MiSTer's clock.
- `set_ini` denies `MAIN`, `SHARED_FOLDER`, `DEBUG`, `BOOTCORE` and array keys; `LOG_FILE_ENTRY`
  is allowed on purpose (Zaparoo's tracking setup needs it).
- Raise `MisterError` (a `ToolError`) for anything the model or user can act on; say what to do.
- Log to **stderr only**, through `logsafe`. stdout is the MCP stdio transport.
- Every tool has a `title`, explicit `ToolAnnotations` (`open_world_hint=False`), and constrained
  args via `Annotated[..., Field(...)]`. `test_tools.py` enforces this. Destructive = can lose
  unsaved progress or a card's contents.
- Zaparoo Core, Main_MiSTer and mrext are GPL-3.0: cite facts from their source, never copy code.

## Zaparoo facts the code depends on (zaparoo-core docs/api, read 2026-10-13, v2.20.0)

- `run` takes ZapScript text and waits for the launch (30 s server timeout); errors carry
  `data.category` (`media_not_found`, `launch_repair` + `data.reason`, `busy`, ...).
- `media.meta {mediaId}` → `media.zapScript`, `media.title.name`, `media.isMissing`.
- `media` → `{database: {exists, indexing, totalMedia}, active: [ActiveMedia]}`; `media.active` →
  ActiveMedia or null.
- `launchers` → `misterCore: {name, file, mglPath}`; `name` is what MiSTer.ini sections use.
- `tokens` → `{active: [...], last}` with `uid` and `scanTime`.
- `stop` on MiSTer returns to the menu (`StopForMenu`).
- Configuring any `api_keys` makes Core 401 every key-less non-localhost request.

## Commands

```sh
pip install -e ".[dev]" && pytest && ruff check . && ruff format --check . && mypy
mcp-server-misterfpga simulate          # two fake MiSTers; prints the export line for another terminal
mcp-server-misterfpga check --host <ip> [--ssh --ssh-key K] | doctor | call <tool> k=v | serve [--http]
MISTERFPGA_MQTT_HOST=<broker> mcp-server-misterfpga track   # the play tracker (MISTERFPGA_MQTT_*)
python scripts/sync_shared.py --check   # shared files match shared.lock
```
